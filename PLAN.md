# План разработки photo-sorter

## Описание

Консольное TUI-приложение на Go для организации фотографий и видео с разных устройств.

Основные возможности:
- Сканирование исходных папок
- Определение даты съёмки по приоритету: EXIF/видео-метаданные → парсинг имени файла → mtime
- Поиск и пропуск дубликатов
- Сортировка по папкам по датам (`YYYY/MM/DD/`)
- Поддержка Live Photos (`.HEIC` + `.MOV`)
- Консольный TUI на `bubbletea` с прогрессом, предпросмотром и режимом `dry-run`

## Структура проекта

```
photo-sorter/
├── cmd/
│   └── main.go              # точка входа (TUI по умолчанию)
```

## Что уже реализовано

### TUI-скелет (`tui/`)

Полноценная навигация по 6 экранам со стрелками `←` / `→` (назад / вперёд):

1. **Выбор источника** — браузер папок. `↑/↓` — курсор, `Enter` — открыть папку, `Backspace` — вверх, `Пробел` — выбрать источник, `→` — далее.
2. **Выбор цели** — аналогичный браузер. `←` — назад, `→` — далее.
3. **Настройки** — шаблон папок (пресеты + свой формат), булевы переключатели (Live Photos, видео, dry-run). `↑/↓` — курсор, `Enter/Пробел` — изменить, `←/→` — навигация.
4. **Сканирование** — прогресс-бар (сейчас симуляция 3 секунды). `←` — назад, `Enter` — начать заново после завершения, `Esc` — выход.
5. **Предпросмотр (dry-run)** — заглушка.
6. **Копирование** — заглушка.

### Internal-пакеты

- **`scanner`** — рекурсивный `filepath.WalkDir`, сбор метаданных (путь, размер, расширение, mtime).
- **`dateresolver`** — структура готова, но пока только fallback на `mtime`. EXIF и парсинг имён — TODO.
- **`deduper`** — двухуровневый детектор дубликатов (размер → `xxhash`). Фильтрация Live Photos. Unit-тесты готовы.
- **`sorter`** — базовое построение дерева: дата → `targetRoot/layout/name`. Коллизии и Live Photos — TODO.
- **`copier`** — базовое копирование через `io.Copy`, поддержка `dry-run`. Коллизии и отмена — TODO.
- **`logger`** — запись в файл с timestamp.

## Неделя 1: «Движок дат» (dateresolver)

### 1.1. Приоритет определения даты

Для каждого файла:
1. **EXIF / видео-метаданные** (`DateTimeOriginal`, `CreateDate`)
2. **Парсинг имени файла** по известным паттернам
3. **`mtime`** (fallback)
4. Если ничего не подошло → `unsorted/`

### 1.2. Мульти-паттерн парсер

Реестр паттернов — каждый паттерн это функция `func(string) (time.Time, bool)`.

Поддерживаемые паттерны:
- `Screenshot YYYY-MM-DD at HH.MM.SS`
- `YYYY-MM-DD HH.MM.SS`
- `IMG_YYYYMMDD_HHMMSS`
- `VID_YYYYMMDD_HHMMSS`
- `PXL_YYYYMMDD_HHMMSSmmm`
- `signal-YYYY-MM-DD-HH-MM-SS`
- `IMG-YYYYMMDD-WA####`
- `YYYYYMMDD_HHMMSS`

Если не матчится — fallback на `mtime`.

> **Реализовано** в `internal/dateresolver/`:
> - `exif.go` — чтение EXIF через `goexif`
> - `filename.go` — реестр из 8 парсеров имени файла
> - `dateresolver.go` — приоритет: EXIF → имя → `mtime` → `unsorted`

### 1.3. Edge case: одинаковые имена из разных устройств

Если в целевой папке файл уже существует:
- Сравниваем по хешу (`xxhash`).
- Хеши совпадают → пропускаем (дубль).
- Хеши разные → суффикс: `IMG_1234_1.jpg`, `IMG_1234_2.jpg`.

### 1.4. Edge case: Live Photos

iPhone создаёт пары `IMG_1234.HEIC` + `IMG_1234.MOV`. `sorter` должен распознавать их по базовому имени и сортировать рядом.

## Неделя 2: Дедупликация и сканер

### 2.1. Модуль `scanner`
- Параллельная обработка нескольких исходных папок через `errgroup`.
- Фильтрация по расширениям (фото + видео).

### 2.2. Модуль `deduper`
- **Быстрая**: группировка по размеру.
- **Точная**: `xxhash` внутри групп одинакового размера.
- Дедупликация работает **глобально** по всем исходным папкам.
- Live Photos (`.HEIC` + `.MOV` с одним basename) не считаются дублями друг друга.

### 2.3. CLI-прототип

Работает без TUI:
```bash
go run . --source ~/Photos/iPhone --source ~/Photos/Android --target /Volumes/ExternalDisk --dry-run
```
Выводит JSON или текстовый отчёт.

## Неделя 3: Интеграция TUI с движком

### 3.1. Экран сканирования (реальный)
- Запуск `scanner.Scan()` с прогрессом.
- Отображение статистики: найдено файлов, определено дат, дублей.

### 3.2. Экран предпросмотра (dry-run)
- Дерево целевой структуры.
- Список дублей.
- Список `unknown_date`.
- Подтверждение перед копированием.

### 3.3. Экран копирования
- Прогресс-бар с процентами.
- Счётчики: скопировано, пропущено, ошибки.
- Поддержка отмены (`Esc`).

## Неделя 4: Видео и логирование

### 4.1. Видео
- Для `.mov`, `.mp4` вызываем `exiftool` как внешний процесс.
- Если `exiftool` не найден → fallback на `mtime`.

### 4.2. Логирование
После каждого запуска создаём лог:
```
2024-04-14_scan.log
  Скопировано: 1240
  Пропущено (дубли): 340
  Unknown date: 12
  Ошибки: 0
```

### 4.3. Обработка ошибок
- Недостаточно места на диске — проверка перед копированием.
- Потеря диска во время копирования — сообщение и сохранение лога прогресса.
- Файлы без прав на чтение — пропуск, запись в лог.

## Неделя 5: Edge cases, тесты и отладка

### 5.1. Тестовая «ферма»

Создать `testdata/` с фейковыми файлами с реальными именами:
- iPhone (`IMG_...`)
- Android (`VID_...`, `IMG_...`)
- Screenshots
- WhatsApp
- Unknown (`photo.jpg`, `DSC_1234.png`)

### 5.2. Unit-тесты
- `dateresolver_test.go` — каждый паттерн + edge cases.
- `deduper_test.go` — дубли, разные файлы с одинаковыми именами, Live Photos.
- `sorter_test.go` — построение дерева.

## Неделя 6: Финал

- Сборка: `go build -o photo-sorter cmd/main.go`.
- Документация в `README.md`.
- Первый запуск на реальных данных:
  1. Подключить внешний диск.
  2. Запустить `dry-run`.
  3. Проверить даты и дубли.
  4. Запустить реальное копирование.

## Правила безопасности

1. **Копируй, не перемещай.**
2. **Всегда dry-run перед реальным запуском.**
3. **Сохраняй лог** каждой операции.
4. **Unknown date → `unsorted/`**, никогда не терять файл.
